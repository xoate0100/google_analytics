# Observability Guide

This document describes the observability features implemented in the MCP Google Marketing server, including logging, operation envelopes, pre-checks, post-checks, and rollback mechanisms.

## Logging

### Logger Implementation

The server uses **Pino** for structured JSON logging. The `PinoLogger` class implements the `ILogger` interface and provides:

- Structured JSON output
- Correlation ID support
- Child context support
- Configurable log levels
- Pretty printing for development

### Log Levels

- `debug` - Detailed debugging information (level 20)
- `info` - General informational messages (level 30)
- `warn` - Warning messages (level 40)
- `error` - Error messages (level 50)

### Log Format

All logs are JSON-formatted for easy parsing:

```json
{
  "level": 30,
  "time": 1234567890000,
  "msg": "Operation completed",
  "opId": "01234567-89ab-7def-0123-456789abcdef",
  "opName": "ga4.report.run",
  "property": "properties/123456789"
}
```

### Correlation IDs

Every operation includes correlation identifiers:

- `opId` - Operation ID (UUID v7 format, generated by `generateOpId()`)
- `idempotencyKey` - Idempotency key (SHA-256 hash of request + target)
- `traceId` - Distributed tracing ID (future: for cross-service tracing)

### Child Context

Loggers support child contexts for scoped logging:

```typescript
const childLogger = logger.child({ opId: "abc123", property: "properties/123" });
childLogger.info("Operation started"); // Includes opId and property in all logs
```

### Configuration

Set log level via environment variable:

```bash
LOG_LEVEL=debug  # Options: debug, info, warn, error
```

For pretty-printed logs in development:

```typescript
const logger = new PinoLogger({ level: "info", pretty: true });
```

## Operation Envelope

Every operation is wrapped in an **operation envelope** that provides:

- Operation tracking and correlation
- Idempotency support
- Pre-check validation
- Post-check verification
- Rollback capability
- Full audit trail

### Envelope Structure

```typescript
interface OperationEnvelope {
  opId: string;                    // UUID v7 operation ID
  opName: string;                  // Tool name (e.g., "ga4.report.run")
  idempotencyKey: string;          // SHA-256 hash for idempotency
  timestamp: string;               // ISO 8601 timestamp
  actor: string;                  // "user" or "system"
  target: OperationTarget;        // Product and resource identifiers
  request: { args: Record<string, unknown> };  // Operation arguments
  precheck?: Precheck;            // Pre-execution validation
  attempt?: Attempt;              // Retry attempt metadata
  result?: OperationResult;       // Operation result
  postcheck?: Postcheck;          // Post-execution verification
  rollback?: Rollback;            // Rollback information
  latencyMs?: number;             // Operation latency
  warnings?: string[];            // Warnings during execution
  notes?: string;                 // Additional notes
}
```

### Creating an Envelope

```typescript
import { createOperationEnvelope } from "../core/envelope.js";

const envelope = createOperationEnvelope({
  opName: "ga4.report.run",
  actor: "user",
  target: { product: "ga4", propertyId: "properties/123456789" },
  request: { args: { property: "properties/123456789", ... } }
});
```

### Operation ID Generation

Operation IDs use UUID v7 format (timestamp-based):

```typescript
import { generateOpId } from "../core/envelope.js";

const opId = generateOpId(); // e.g., "01234567-89ab-7def-0123-456789abcdef"
```

### Idempotency Key

Idempotency keys are computed from request and target:

```typescript
import { computeIdempotencyKey } from "../core/envelope.js";

const key = computeIdempotencyKey(
  { args: { property: "properties/123", ... } },
  { product: "ga4", propertyId: "properties/123" }
); // SHA-256 hash (first 32 chars)
```

## Pre-Check Validation

Pre-checks validate conditions before executing an operation:

```typescript
interface Precheck {
  capability: boolean;      // Required capability available?
  exists: boolean;         // Resource exists?
  conflicts: string[];     // List of conflicts
}
```

### Pre-Check Implementation

```typescript
import { performPrecheck } from "../core/precheck.js";

const precheck = await performPrecheck({
  capability: { product: "ga4", capability: "data_api" },
  exists: { product: "ga4", resourceId: "properties/123" },
  conflicts: []
}, capabilitiesRegistry, logger);
```

### Pre-Check Results

- `capability: true` - Required capability is available
- `exists: true` - Resource exists (for update/delete operations)
- `conflicts: []` - No conflicts detected

If pre-check fails, a `PreconditionError` is thrown with reason `"precheck_failed"`.

## Post-Check Verification

Post-checks verify operation results after execution:

```typescript
interface Postcheck {
  readBack: boolean;       // Read-back verification performed?
  stateMatch: boolean;      // State matches expected?
  discrepancies?: string[]; // List of discrepancies
}
```

### Post-Check Implementation

```typescript
import { performPostcheck } from "../core/postcheck.js";

const postcheck = await performPostcheck({
  readBack: async () => {
    // Read back the created/updated resource
    return await getResource(id);
  },
  expectedState: { name: "Expected Name", ... },
  stateMatcher: (actual, expected) => {
    // Compare actual vs expected state
    return actual.name === expected.name;
  }
}, logger);
```

### Post-Check Results

- `readBack: true` - Resource was read back successfully
- `stateMatch: true` - State matches expected values
- `discrepancies: []` - No discrepancies found

If post-check fails, discrepancies are logged and rollback may be triggered.

## Rollback Mechanism

Rollback is triggered when:

1. Post-check fails (state mismatch)
2. Operation partially succeeds
3. Explicit rollback requested

```typescript
interface Rollback {
  needed: boolean;         // Rollback required?
  action: string | null;   // Rollback action identifier
  executed: boolean;       // Rollback executed?
  success: boolean;        // Rollback successful?
}
```

### Rollback Execution

Rollback actions are executed automatically when `rollback.needed === true`:

```typescript
if (envelope.rollback?.needed) {
  await executeRollback(envelope.rollback.action, envelope);
}
```

## Operation Result

Operation results include status and data:

```typescript
interface OperationResult {
  status: "success" | "error" | "partial";
  data?: unknown;          // Operation result data
  error?: MCPError;        // Error if status is "error"
  resourceId?: string;     // Created/updated resource ID
  etag?: string;          // ETag for cache validation
}
```

## Logging Best Practices

1. **Structured Logging**: Always use structured JSON logs with context objects
2. **Correlation**: Include `opId`, `idempotencyKey` in all log entries
3. **Context**: Include relevant context (property, account, etc.) in each log
4. **PII Redaction**: Never log sensitive data (use hashes or redaction)
5. **Level Appropriateness**: Use appropriate log levels:
   - `debug`: Detailed debugging information
   - `info`: Normal operation flow
   - `warn`: Recoverable issues or deprecations
   - `error`: Errors requiring attention

### Example Logging

```typescript
// Start operation
logger.info("Executing ga4.report.run", { 
  opId: envelope.opId,
  property: validatedRequest.property 
});

// Operation complete
logger.info("ga4.report.run completed", {
  opId: envelope.opId,
  property: validatedRequest.property,
  rowCount: response.rowCount
});

// Error logging
logger.error("ga4.report.run failed", error, {
  opId: envelope.opId,
  property: validatedRequest.property
});
```

## Metrics

### Internal Counters

Metrics are collected internally (future: export to Prometheus/Cloud Monitoring):

- `success` - Successful operations count
- `retries` - Retry attempts count
- `rate_limited` - Rate limit hits count
- `rollback_count` - Rollback operations count
- `p50/p95 latency` - Latency percentiles by tool

### Operation Latency

Latency is tracked per operation:

```typescript
const startTime = Date.now();
// ... execute operation ...
const latencyMs = Date.now() - startTime;
envelope.latencyMs = latencyMs;
```

### Querying Logs

Search logs by:
- `opId` - Find all logs for a specific operation
- `opName` - Find all operations of a type
- `property` - Find all operations for a property
- `error.type` - Find all errors of a type

Example log query (using jq):

```bash
# Find all errors for a property
cat logs.json | jq 'select(.property == "properties/123456789" and .level >= 40)'

# Find all operations for an opId
cat logs.json | jq 'select(.opId == "01234567-89ab-7def-0123-456789abcdef")'

# Find rate limit errors
cat logs.json | jq 'select(.error.type == "QuotaError" and .error.reason == "rate_limited")'
```
